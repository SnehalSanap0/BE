# Handoff — Hindi deepfake audio detection (EfficientNet-B0)

## Project
`d:\BE` — Hindi real/spoof audio classifier, mel-spectrogram + EfficientNet-B0, targeting a paper on deepfake audio detection. Config-driven (`configs/config.py` → `CONFIG` singleton), full pipeline: ingestion → preprocessing → feature extraction → training → evaluation → explainability (Grad-CAM) → deployment (Flask/Gradio).

## Where things stand
- **Main config** (`configs/config.yaml`) now ingests SEA-Spoof only (Hindi, train split, 3000/3000).
- **Legacy multi-source data** still on disk under `data/raw/hindi/{real,fake}`: `real` (Kathbath, 3000), `real_cv_m`/`real_cv_f` (Common Voice Hindi male/female, 750 each), `fake` (IndicSynth, 3000), `fake_sea` (SEA-Spoof spoof, 1500).
- **Prior cross-source factorial work** (see `docs/research_log.md`, entries from 2026-07-20 through 2026-07-24): pooled random splits gave misleadingly perfect metrics (source shortcut learning). A 2×2 factorial over real-source (Kathbath vs Common Voice) × fake-source (IndicSynth vs SEA-Spoof) via `scripts/cross_source_holdout_check.py` showed generalization varies a lot by pairing — `fake_swap_only` (train real=Kathbath/fake=SEA-Spoof) generalized worst (EER 0.40, AUC 0.63). `scripts/confound_check.py` and `scripts/embedding_analysis.py` traced this to channel/silence-statistic differences between sources bleeding into the embedding space as a source-identity shortcut.
- **New direction (2026-08-06 onward):** transcript-paired SEA-Spoof training via `scripts/run_paired_seaspoof_smoke.py` + `configs/config.smoke_seaspoof.yaml` (isolated paths under `*_seaspoof_paired/`). Idea: pairing real/fake by matching transcript removes content as a label cue. Scaled smoke runs from 12 → 500 pairs; all same-source (SEA-Spoof `validation` split for train/val/test) — see the "Accuracy vs. configuration" tracker table near the top of `docs/research_log.md` for every run's numbers. Best same-source run (target_count=500): accuracy 0.9867, f1 0.9865, roc_auc 1.0, eer 0.0.
- **2026-08-09, most recent result:** wrote `scripts/eval_smoke_model_on_legacy_sources.py` — no retraining, just runs the target_count=500 smoke checkpoint (`checkpoints/smoke_seaspoof_paired/best_model.pt`) on random raw clips from the four legacy sources it never trained on. Result: **0.85 overall accuracy** across 60 clips (real=Kathbath 0.60, real_cv_m 0.87, real_cv_f 1.00, fake=IndicSynth 0.93). Encouraging — especially IndicSynth, a different TTS system than SEA-Spoof — but single-seed/single-run, not yet a citable result. Kathbath is the weak point (8/20 misclassified as fake), possibly related to the channel/silence confound already characterized in the factorial work.

## Immediate next step (agreed direction, not yet started)
Run the transcript-paired-training idea through the **proper** cross-source protocol instead of the ad hoc spot check:
1. Switch paired SEA-Spoof ingestion from `split: "validation"` to `split: "train"` at real scale (thousands of pairs) — the smoke config currently uses `validation` only because `train` shards were "too large and ordered poorly for a quick test" (see 2026-08-06 entry); this constraint needs revisiting for a real run.
2. Evaluate on a proper held-out-by-source split (reuse/extend `scripts/cross_source_holdout_check.py`'s pattern) rather than random 60-clip sampling, with multiple seeds.
3. Compare against the earlier (non-paired) factorial rotations to see whether transcript pairing measurably reduces the source-shortcut problem — this is the likely headline paper finding.
